# Decisions

## ADR-001 — Vanilla ESM вместо framework
Статус: принято.

Один компактный интерфейс не оправдывает frontend framework и сборку. Используем HTML/CSS/ES modules.

## ADR-002 — Server profiles вместо единого local progress
Статус: заменяет прежнее локальное решение.

Product Owner потребовал глобальную уникальность имён и раздельный прогресс пользователей. Это невозможно гарантировать только через `localStorage`, поэтому добавлен минимальный same-origin backend с SQLite.

## ADR-003 — Device-bound session token без пароля
Статус: принято.

Ребёнок вводит только имя. При регистрации выдаётся случайный token, hash которого хранится на сервере. Знакомое устройство автоматически продолжает игру. Полноценное восстановление на новом устройстве намеренно не реализуется без PIN/пароля.

## ADR-004 — Явные раунды по 10
Статус: принято.

Каждый раунд содержит ровно 10 ответов, показывает постоянный индикатор и завершается отдельным поздравительным экраном с результатом.

## ADR-005 — SQLite вместо PostgreSQL
Статус: принято.

Для одного процесса, небольшого числа детских профилей и текущего Tailscale deployment SQLite проще и надёжнее отдельной СУБД. Ответы фиксируются короткими transactions и защищены idempotency key.

## ADR-006 — Простая weighted practice
Статус: принято.

Ошибочные пары показываются немного чаще, но не вытесняют случайные примеры.
